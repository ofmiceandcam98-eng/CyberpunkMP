Synced Ambient Traffic

Nothing in the codebase touches ambient traffic today — I searched the client, the server and every .reds. The game's own traffic runs independently on each machine, so two players drive through two different cities that share a street layout. The replication plumbing already exists and works. Ambient cars do not need a new system; they need to stop bypassing the one we have.

What already exists, and what it costs you

Measured from the code, so the plan starts from what is true rather than what would be convenient.

The replication path is real and proven

NotifyVehicleLoad { id, tweak_id, position, rotation, cell_x, cell_y, sequence, authority_epoch, correction } already does server-owns / client-renders, with a duplicate guard added after the multiplying-cars bug and explicit authority handoff via NotifyAuthorityAssigned and NotifyAuthorityRevoked. The client's whole job is SpawnVehicle(tweak_id, position, rotation).

The server never interprets a vehicle model, and that is deliberate

VehicleRecord.Model is a raw TweakDBID the server stores and forwards without understanding — so a server needs no update when the game adds cars. Keep that property; an ambient system that has to know what a car is throws it away.

The cell partition is not yet doing any work

At kCellSize = 6000 all eleven real positions fall in two cells, so nothing is culled. Ambient traffic is the first feature that makes the partition matter — and changing it is flag-day shaped, so it batches with the protocol change rather than going alone.

The cheap win might be the whole win

Phase 1 is deliberately not a step towards phase 2 — it is a question. An identical empty street is synced, costs one tweak, and may be all an RP setting needs. Build the expensive half only after standing in the empty one and deciding it is not enough.
