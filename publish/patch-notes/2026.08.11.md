# 2026.08.11

## Summary
First public build. This runs on game patch **2.31** — upstream CyberpunkMP targets 2.2 and won't start on current Cyberpunk at all, so getting it onto 2.31 was most of the work.

Two players can connect, authenticate, and see each other move around. There is still a crash when a second player spawns, and that's the one thing standing between this and playable sessions. It's narrowed to about ten lines of code and this build ships with markers that pinpoint the exact failing line — so if you crash, your log is genuinely the most useful thing you can give us.

## Fixed
- Fixed the mod failing to start on patch 2.31 — a type-name resolver was silently falling back to the wrong name, so the game rejected the scripts before anything loaded
- Fixed remote players spawning at the wrong position and never moving — position was being read from a transform the game doesn't update as you walk
- Fixed a crash when joining while the character customization state was empty
- Fixed a race where the animation thread read a player's data while the game was still assembling them

## Added
- One log file per launch, in `logs\` next to the mod. Crashes no longer overwrite each other, so relaunching can't destroy the evidence
- Diagnostic markers through the player-spawn path, to identify exactly where the join crash happens
- A version check that warns in the log if your game isn't 2.31

## Known issues
- **Crash when a remote player spawns.** Actively being hunted. If it happens, post your log from `red4ext\plugins\zzzCyberpunkMP\logs\` — the whole file, not a screenshot
- Remote players appear without clothes or weapons. Item names come back empty on 2.31, so gear doesn't transfer. Cosmetic
- Remote player movement speed reads as nonsense, so their animations look wrong
- The `/` key doesn't open chat. A debug menu bar works as a fallback while online
- **Disable Cyber Engine Tweaks.** CET alongside this mod has caused a full GPU hard-lock
